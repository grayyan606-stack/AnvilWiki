## What should you check before grabbing an egg?

- Guardian position and movement pattern
- Distance back to your base
- Your speed while carrying the target
- Players waiting near the nest or return route
- Whether a safer egg gives better expected income per minute

## How do you build a repeatable route?

Time the route without an egg, then time it again while carrying a normal target. Use the slower result, add an escape buffer, and compare it with the spawn cycle in the [Egg Run Planner](/tools/calculators#run-calculator).

<Callout type="tip" title="Leave before the crowd">If several players converge on the same high-value egg, switching targets can protect the whole cycle instead of turning it into a zero-return fight.</Callout>

## When should you attempt a larger egg?

Attempt it after your normal route has spare time and your speed exceeds the minimum by enough to handle carrying penalties, path mistakes, and guardian movement. Use the [egg guide](/eggs/egg-guide) to compare target quality.

## How do you scout a route before committing?

Walk the complete route without carrying an egg. Identify the nest approach, turns that hide the guardian, narrow passages, and the point where another player can intercept you. Then return to the base using the exact path you intend to use under pressure. Timing only the outward trip leaves out the most important half of the attempt.

Repeat the empty route until the time is stable. Next, test with an egg you can afford to lose. Record whether carrying changes movement or path choice in your current session instead of assuming a fixed penalty. The safe planning time is a normal successful return plus enough buffer for the delays you actually saw.

## How should you read the guardian?

Observe at least one full movement cycle from a safe position. Note where the guardian turns, how long useful openings last, and which paths force you close to it. Treat the observation as local to the current game state. If the guardian changes direction because of another player, wait for the pattern to settle before calling the route predictable.

Choose a launch cue that is visible and repeatable, such as the guardian passing a landmark. “Go when it feels safe” is hard to improve because failures cannot be compared. A defined cue lets you move it earlier or later after each test.

## How do other players change the decision?

Another player can alter both egg availability and escape space. Before approaching, scan the nest, likely return lanes, and your base entrance. If several players are waiting for the same target, the expected value may fall even when the egg itself is excellent. A lower-value uncontested route can produce more successful returns over the same period.

Do not rely on cooperation from strangers for a route that only works when nobody interferes. If the server becomes crowded, choose a different target, practice movement, or use the time for training. Leaving a bad attempt is a strategy decision, not wasted progress.

## What is the difference between entry, pickup, and return success?

These are three separate checkpoints:

| Checkpoint | Question |
| --- | --- |
| Entry | Can you reach the biome or nest? |
| Pickup | Can you take the intended egg under current conditions? |
| Return | Can you bring it to the base and complete the loop? |

A guide that proves only entry cannot promise a successful steal. Record the checkpoint reached on failed attempts. Repeated entry failures suggest more speed or route practice; pickup failures may be timing or competition; return failures point to carrying conditions, pursuit, or an insufficient buffer.

## How do you compare two routes?

Test each route for the same number of complete opportunities. For every attempt, record total loop time and whether the egg returned. Compare successful returns per unit of time, then consider the actual value of the returned eggs. Do not compare the fastest successful run on one route with the average of all attempts on another.

The [Egg Run Planner](/tools/calculators#run-calculator) helps organize route time, spawn interval, and a buffer, but it cannot know competition or success probability. Keep failed attempts in the decision. A route that is twice as fast but succeeds rarely may still be worse.

## What should you do after a failed steal?

Identify the first failed checkpoint before trying again. If another player took the egg, changing guardian timing will not solve the problem. If the guardian caught the return, test a safer cue or increase the speed margin. If you missed a turn, practice the empty route until it is automatic.

Avoid immediately risking a more valuable egg to “recover” the loss. Use the next ordinary opportunity as a controlled test. One changed variable per attempt makes the result useful.

## A practical pre-run checklist

Confirm the official experience, current route, guardian cue, nearby players, target fallback, current speed, and base return path. Decide in advance what condition will make you abort. After the run, record the outcome while the reason is still clear. For choosing among egg targets, continue to [Egg Guide](/eggs/egg-guide); for movement planning, use the [speed training guide](/guides/speed-training).

## How do you turn repeated attempts into a better decision?

Use a small attempt log instead of remembering only the best run. For each try, mark whether you reached the egg, picked it up, and returned successfully, then add one short reason for the first failure. Keep route, target, and speed stable for a few attempts before changing one factor. This makes it possible to tell whether extra training, a safer turn, a different target, or a quieter server actually improved the result.

Do not publish a universal success rate from a personal sample. Your route execution, device, latency, other players, and current game version all affect the observation. The useful conclusion is narrower: which route was more reliable for the recorded conditions and what evidence would make you retest it.
