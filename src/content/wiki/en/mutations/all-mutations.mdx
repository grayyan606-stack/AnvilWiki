## Which mutation is best?

Spirit Bloom has the highest tracked multiplier. Rainbow is the strongest of the widely reported natural egg mutations. The better practical choice still depends on the pet's base income, size, and how many attempts the acquisition method requires.

<Callout type="warn" title="Size is separate">Do not apply the mutation multiplier twice. Size and mutation are separate factors; use the exact values shown on your pet card.</Callout>

Use the [Mutation Comparison](/tools/calculators#mutation-calculator), then read the [Sakura Incubator guide](/mutations/sakura-incubator) for Bloom outcomes.

Sources: [GAMES.GG mutation guide](https://games.gg/roblox/guides/steal-an-egg-mutations-guide/) and [Sakura Incubator reporting](https://beebom.com/steal-an-egg-sakura-incubator-guide/).

## What does a multiplier change?

A mutation multiplier scales the base value to which the game applies it. If a pet's verified base income is `B` and the visible mutation multiplier is `M`, the mutation-only estimate is `B × M`. This is arithmetic, not proof that a displayed card is unmodified.

Before calculating, decide whether the number you copied is a base rate or a final contribution. If the card already shows the mutation effect, entering it as the base and multiplying again will overstate income. Keep size as a separate input only when its effect is also shown or otherwise supported.

## How do you compare two mutations fairly?

Use the same pet base and size condition for both sides. Change only the mutation multiplier. The difference then describes the mutation choice rather than a mixture of pet, size, and copy count.

For an existing pet, compare its live final contribution with the candidate outcome. For a planned egg, label results as conditional because the hatch, eligibility, and mutation outcome may not be guaranteed. The [Mutation Comparison](/tools/calculators#mutation-calculator) shows the arithmetic without adding hidden rates.

## Why is the highest multiplier not always the next goal?

Acquisition paths differ. Natural mutated eggs depend on finding and returning the right target, while Bloom outcomes use the Cherry Blossom system described in the [Sakura Incubator guide](/mutations/sakura-incubator). Time, route failures, unlocks, crystals, and the egg's base value all affect the practical decision.

A more available lower multiplier on a strong base can be a better near-term improvement than a rare top outcome on an unsuitable egg. Compare the slot improvement and resource cost, not only the multiplier column.

## What is known about natural mutation odds?

This page does not publish exact natural-spawn odds because the checked sources do not provide evidence strong enough for a permanent table. A colored egg appearing in one session proves that the outcome can occur, not its probability.

To estimate a rate, define the eligible opportunities, count every one, record outcomes, and keep the game version and event conditions. A small personal sample can guide expectations but should be labeled as such. Do not convert a handful of sightings into a precise global percentage.

## How should Incubator chances be read?

The reported Bloom and Spirit Bloom percentages belong to the cited update period and should be checked against the live Incubator interface. Even when the displayed chance is current, a rare outcome is not promised on a small number of attempts. Avoid describing a likely result as guaranteed or treating a rare result as the normal value of every egg.

Record the input egg, resource cost, displayed outcome labels, and result for each attempt. Keep account identifiers out of public evidence.

## How do copies and mixed mutations work in a plan?

Group only identical pet configurations. If three copies have different mutation or size states, calculate each configuration separately and add the contributions. Applying one strong multiplier to every copy creates an undocumented estimate.

When replacing a slot, calculate the difference between the candidate and the removed pet. The full candidate income is not the entire upgrade. This matters most in established bases where the weakest slot already contributes substantially.

## What should you verify after a patch?

Check the mutation names, displayed multipliers, acquisition paths, Incubator requirements, and whether the card display includes modifiers. An update can change one field without replacing the whole system. Preserve earlier values as historical scope when they explain older guides.

Update the Evidence panel date only after a real review and add material conflicts to the [data corrections log](/updates/data-corrections). A newly edited paragraph does not make an old observation new.

## How can you report a mutation correction?

Submit the page URL, pet or egg, exact visible label, base and final values if available, size state, date, and source through [Contact](/contact). Crop unrelated usernames and never include credentials. The maintainer reviews the evidence before changing the table.

For choosing a target after the arithmetic, compare the result with the current weakest slot in the [income calculator](/tools/income-calculator) and review the acquisition route in the relevant biome guide.

## How should you preserve evidence for a mutation result?

Capture the pet or egg identity, visible mutation label, base value if the interface shows one, final displayed value, size state, acquisition method, date, and game version when available. Keep the original observation beside any calculated multiplier. Dividing final value by base value can suggest a relationship, but it does not prove the game applies every modifier in that order.

If two records disagree, check whether one already includes size, copies, event effects, or another mutation before calling either one wrong. Preserve both dated records until matching conditions can be tested. This is slower than copying a clean universal table, but it prevents mixed inputs from becoming false precision.
