## Why do pet totals disagree?

Articles published before the Cherry Blossom update describe nine standard biomes. Newer trackers add Cherry Blossom as the tenth and include its pets, producing a larger total. Search snippets can keep showing the older number after the game changes.

## How should you compare pets?

Start with base income, then account for mutation, size, and the number of copies placed at your base. Use the [Pet Income Calculator](/tools/calculators#income-calculator) for your actual values.

Reference points: [recent post-update index](https://www.eldorado.gg/blog/roblox-en/steal-an-egg-all-pets-index/), [earlier tracked egg and pet list](https://beebom.com/steal-an-egg-all-eggs/), and the live in-game Index.

## What does each table field mean?

The pet name and biome identify the record. Rarity is the label reported for that pet, while base income is intended to exclude mutation and size effects. The evidence label describes how confidently the fields can be used together. A row is not complete if a source proves the name but the income came from an unrelated screenshot.

Use the filters to narrow a decision, not to claim that missing pets do not exist. The current table is a verified subset. A blank result can mean that the selected combination has not yet been recorded under this editorial standard.

## How should you verify a pet in your own game?

Open the live pet card and record the name, rarity, biome or egg source, displayed income, mutation, size, and date. Preserve enough context to tell whether the displayed number is a base value or a final contribution. If the game provides an Index entry, compare its labels with the card.

For a clean base-rate observation, prefer a normal-sized, unmutated copy when available. If only a modified pet is visible, publish the displayed value as modified or leave base income unresolved. Dividing by an assumed multiplier can introduce a second unverified claim.

## How do you compare records from two sources?

First align the definitions. Check that both pages refer to the same pet spelling, update period, biome, rarity, and income unit. Then check whether one value includes size or mutation. A newer publication date is useful, but it does not automatically make an unsourced table more reliable than a dated in-game observation.

If the definitions match and values disagree, keep both in the research notes and mark the public row as conflicting. Do not average them. Income is a game value, not a noisy opinion poll.

## Why are mutation and size excluded from sorting?

Sorting a base index by final card values would mix several variables. A lower-base pet with a strong mutation could appear above an unmodified high-base pet, leaving readers unable to reproduce the order. The base table provides one comparison layer; the [mutation guide](/mutations/all-mutations) and [income calculator](/tools/income-calculator) add the conditions that apply to your copy.

When comparing two pets for a slot, use their actual displayed contributions under the same current conditions. The index helps find candidates; it does not override the live card.

## How should missing records be added?

A proposed row should include all required fields, the check date, and an attributable source. De-identify screenshots and keep the relevant UI labels visible. Submit the affected page and evidence through [Contact](/contact). Contributions are reviewed before publication and do not automatically update this table.

Do not infer an entire biome roster from a claimed total. Add pets individually as their identity and values are checked. That approach grows more slowly, but every new row adds usable information instead of enlarging an unverifiable list.

## How can you use the index for progression?

Filter to biomes you can return from reliably, then compare candidates with the weakest occupied slot. Consider the income difference, route duration, likely failed attempts, and any resources needed after hatching. A high headline rate in an inaccessible zone is not an immediate upgrade.

For early play, filling an empty slot captures the full new contribution. Later, replacement value becomes the candidate minus the pet removed. Use the [beginner guide](/guides/beginner-guide) for that order and the [best pets guide](/pets/best-pets) for current high-end targets.

## When should this page be rechecked?

Recheck after a game update adds a biome, egg, pet, mutation, rebalance, or Index change. Also recheck a row when a reader supplies current conflicting evidence. Update the evidence date only after an actual review, and preserve version context in the [data corrections log](/updates/data-corrections).

## What makes a pet record complete enough to publish?

A useful record identifies the pet, where the observed egg or pet belongs, the displayed base contribution or an explicit unknown value, and the date and conditions of the check. Mutation, size, copies, or event bonuses should be separate fields rather than silently folded into a “base” number. If the pet name is visible but its value is not, publishing the identity with an unknown value is more accurate than reconstructing one from an unlabeled screenshot.

New records should also link to the route or biome context that makes them actionable. An index is strongest when a reader can move from identity to acquisition, comparison, and verification without assuming that every row is equally current.
